# Upbit 자동 판정과 원자적 GAM 정산

## 운영 경계

- BTC·ETH·SOL·XRP·DOGE·ADA의 Upbit KRW 시장만 지원한다.
- LLM은 결과를 판정하지 않는다. 관측 시각 직전 정확한 1분 캔들의 종가만 사용한다.
- 종가가 정수 기준가를 **초과**하면 Yes, 같거나 낮으면 No다.
- 현재 시세, 다른 시장, 인접 시각 캔들로 대체하지 않는다.
- 자료를 확인할 수 없으면 대기한다. 관측 후 24시간이 지났는데도 확인할 수 없으면 Cancelled로 환불한다. 늦게 조회했더라도 정확한 공식 캔들을 확인하면 사실에 따른 판정이 가능하다.
- GAM은 현금화 불가 사이버 자산이다. 실제 사용자나 참여량을 만들지 않는다.

## 실행

`AUTO_RESOLVE_UPBIT=true`인 경우에만 서버가 60초마다 실행한다. 스키마 초기화 실패 시 자동 정산은 비활성화된다. 관측 시각 후 최소 5초의 자료 반영 여유를 둔다. API 429 응답은 이번 조회 묶음을 중지하며, 모든 조회 경로에 요청 간격을 적용한다.

1. 공식 Upbit 캔들을 조회하고 시장·시각·종가를 검증한다.
2. 단일 PostgreSQL 클라이언트에서 트랜잭션을 시작한다.
3. 이슈, 베팅, 사용자 순으로 잠금한다. 조회 당시 규칙과 잠금 후 규칙이 일치해야 한다.
4. 결과, 사용자 잔액, rewards, gam_transactions, issue_settlements, settlement_credits를 함께 기록한다.
5. 전부 성공해야 COMMIT한다. 실패 시 모든 잔액·기록을 ROLLBACK한다.
6. 알림은 COMMIT 뒤에 별도로 처리한다. 알림 실패로 지급을 재실행하지 않는다.

기존 승자 분배는 `floor(총 베팅액 × 95 / 100 × 개인 승자 베팅액 / 전체 승자 베팅액)`이다. Draw·Cancelled·승자 없음은 원금 전액 환불이다. 계산은 BigInt로 하며, 잔액 INTEGER 상한 초과 시 전체 정산을 중단한다. 과거 rewards/정산 원장 흔적과 미확정 결과가 충돌하면 자동 지급을 하지 않고 대조 검토가 필요하다.

베팅 등록도 같은 이슈 잠금으로 시작하며, 잠금 대기 후 DB 시계로 마감을 다시 확인한다. 잔액 차감·베팅·거래 원장·참여 금액 갱신 역시 한 트랜잭션이다.

## 신규 이슈 API

정상 관리자 인증으로 `POST /api/admin/issues`에 `resolution_params`를 보낸다. `end_date`와 `betting_end_date`는 명시적 UTC ISO다. 원래의 `endDate`/`bettingEndDate` 별칭도 지원한다.

```json
{
  "version": 1,
  "provider": "upbit",
  "market": "KRW-BTC",
  "metric": "minute_close",
  "operator": "gt",
  "threshold": 117000000,
  "observation_at": "2026-10-06T09:00:00.000Z",
  "missing_data_policy": "cancel_after_24h"
}
```

공개 description에 정확한 정수 기준과 단 하나의 식별자가 있어야 한다.

```text
기준가가 117,000,000원을 초과하면 YES
운영 식별자: YEGAM-BTC-20261006-1800-KRW-v1
```

식별자 날짜·시각은 KST다. description, 구조화 규칙, 판정 시각은 일치해야 한다. 제목에 직접 숫자 원 가격을 표시할 경우 하나의 목표가만 표시하며 규칙과 일치해야 한다. 한국어 단위 제목도 허용하지만 공개 description의 전체 정수 기준이 최종 기준이다.

이전 게시 방식과의 호환을 위해 위의 엄격한 식별자/기준 문구가 있으면 규칙을 추론해 저장할 수 있다. 일반 문장만으로 자동 정산을 켜지는 않는다. 동일 코인·판정 시각·v1 회차의 중복 등록은 DB 고유키로 거부한다. 참여 또는 결과 확정 후 규칙과 판정/베팅 마감 시각을 변경할 수 없다.

## 검증·운영 API

모두 정상 관리자 인증이 필요하다.

- `GET /api/admin/settlements/status`: 기능 상태와 미확정 대상 조회.
- `POST /api/admin/settlements/run` + `{"dry_run":true}`: 지급·DB 변경 없는 공식 판정 검사.
- `POST /api/admin/settlements/run` + `{"dry_run":false}`: 기능이 활성화된 경우 원자적 정산 실행.
- 기존 `POST /api/admin/issues/:id/result`도 같은 정산 서비스를 사용한다. 구조화 Upbit 이슈의 Yes/No는 공식 판정과 일치해야 한다.

첫 이관은 기존 승인된 이슈 136–143 중 미확정이고 엄격한 규칙이 검증되는 것만 대상으로 한다. 다른 과거 이슈는 임의 판정하지 않는다. 규칙을 검증하지 못한 이관 대상은 경고 로그로 남긴다.

## 배포 전 필수 설정

Railway에 서로 다른 안전한 32자 이상 값을 설정해야 한다. 실제 값을 코드, 커밋, 대화, 문서에 넣지 않는다.

- `JWT_SECRET`
- `SESSION_SECRET`
- `ADMIN_JWT_SECRET`
- `ADMIN_SECRET_KEY`는 에이전트 관리 API를 사용할 때 반드시 안전하게 설정한다. 누락·빈 헤더·32자 미만 값은 거부한다.

기존 공개 코드의 인증키는 계속 사용하지 말고 교체한다. JWT/세션 키 교체는 기존 로그인을 만료시킨다. 관리자 비밀번호 자체는 이 변경에서 바꾸지 않는다. 인증 없는 진단·설정/관리 테이블 수정 경로는 제거했고, `/api/admin` 전체에 관리자 인증을 추가했다.
